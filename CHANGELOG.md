# Changelog

## 0.1.0

Initial public release. Extracted from the in-tree thermal camera middleware of the handheld thermal imager firmware.

- `tcam_init()` binds a caller-owned object to one explicit model and a caller-owned ops table, and rejects a NULL object, an unknown model and every missing callback. There is no runtime model detection: each driver function checks the bound model and fails without touching the port when the object belongs to the other driver.
- MINI212 driver: `0x55AA` command framing with length byte, XOR checksum and `0xF0` tail; writes check a `0x00` acknowledgement, reads receive the acknowledgement and a response frame. Covers the status, digital-video, settings, focus and custom-data pages; image freeze, colour, tone, preset, spatial/temporal denoising, detail enhancement, brightness, contrast, mirror, zoom centre/ratio and frame frequency; digital type, CMOS interface/content and external sync; shutter state, automatic shutter state and interval; bad-point position add and save; measurement range, distance, emissivity, humidity, reflected and atmospheric temperature; single-point and two-point calibration, save and factory restore.
- TM30 driver: `0xF0 | size | 0x36 | class | sub | flag | data | checksum | 0xFF` framing with an additive checksum; responses must echo class/sub with the `0x03` flag and writes answer `0x01`. Covers CID, serial number, model number, FPGA and firmware versions and build dates, camera calibration date, time, reset, save, factory restore, shutter/background/vignetting correction, auto-shutter mode and timed interval, cursor display/position/bad-point control, brightness, contrast, detail enhancement, both denoisers, palettes, mirror, rotate, stream format, YUV resolution, measurement enable/unit/range, emissivity, distance, reflected and atmospheric temperature, humidity, calibration parameters and calibration state. Version and date replies are packed BCD and are decoded to binary; time and measurement values are binary.
- Stream path: `stream_start()` arms the port for the exact frame size (MINI212 197,632 bytes, TM30 174,720 bytes) and starts capture; acquire/release hand whole frames back and forth without the library allocating; decode validates the embedded parameter block and returns read-only MT and YUV matrix views plus minimum/maximum/average temperature and coordinates. MINI212 coordinates are returned as reported; TM30 normalised coordinates (0-1000) are scaled to the 96x96 MT grid.
- Units are part of the API and are range-checked before any exchange: distances in dm, emissivities and relative humidity in percent (TM30 humidity per mille), temperatures with explicit `mult10`, `mult100`, `add100_mult10` and `add300_mult10` fields.
- New for the standalone release: `README.md`, `LICENSE`, `doc/api.md`, `doc/porting.md`, `examples/tcam_port_template.c` and `build.sh`. The six files under `src/` are unchanged.
- Known gaps, by design: no transport, power, reset, model detection or recovery policy; MT words are returned raw instead of converted to temperatures; little-endian IEEE-754 targets only; no locking and no interrupt-context safety; no host-side test suite and no mock device, so the example is a compile-only skeleton and hardware behaviour is verified on the target only. The stream layout assumes the MINI212 MT+YUV422 content mode and the TM30 MT+YUV format at 240x240 YUV resolution; other content or resolution settings change the device's frame size and are outside the decoded contract.
